How k-anonymity protects your password

The plaintext password never leaves this device. A local SHA-1 digest is computed in your browser using the Web Crypto API. Only the first 5 hexadecimal characters (20 bits) are transmitted to the API endpoint. The service returns a list of matching hash suffixes (~500 hashes), and the browser compares the remaining 35 characters entirely locally in memory.

07 / AUTHENTICATION REFERENCE NOTES NIST SP 800-63B
  1. 01
    Length trumps arbitrary complexity rules§5.1.1.2

    Forcing arbitrary composition (e.g. 1 uppercase, 1 symbol) prompts predictable human substitutions like P@ssw0rd1!. Long passphrases exponentially widen brute-force search space while remaining straightforward for users to memorize.

  2. 02
    Eliminate periodic forced expiration§5.1.1.2

    Mandating routine 60- or 90-day password changes leads users to select simple incremental variants (e.g., Spring2025! → Summer2025!), degrading organizational security rather than improving it.

  3. 03
    Screen candidate passwords against known breach corpora§5.1.1.2

    Over 80% of credential attacks rely on credential stuffing from prior breaches. An otherwise complex password is compromised on day one if it appears in an adversary's precomputed rainbow table.

  4. 04
    Store hashes with memory-hard KDF algorithms§5.1.1.2

    Legacy hashes like MD5, SHA-1, and NTLM can be computed at billions of operations per second on consumer GPUs. Production systems must utilize memory-hard key derivation functions (Argon2id, bcrypt, scrypt) to throttle offline cracking.
